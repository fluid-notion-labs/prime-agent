## Feature (Nick, 2026-11-18)
A central history of chat sends per provider. When sends approach a provider's per-minute cap (e.g. 20/min for the cf/workers-ai provider today), PAUSE sending (debounce) until a slot frees — converge to the limit rather than erroring. Nick's quota goes 20/min -> 50/min soon, so the limits MUST be editable in the settings/config file.
Also: retry limits per provider (cap retries; a retry counts against that provider's window).

## Design pointers (verify, then adapt)
- Exploration start: crates/pa-core/src/session_engine/ (engine.rs, auto_retry/ — retries already have machinery) and crates/pa-ai/src/providers/. Find where provider chat requests are actually issued — the limiter belongs THERE (engine side), so client sends AND auto-retries both consume the same window.
- Limiter: per-provider sliding 60s window (VecDeque of timestamps is fine; no over-engineering — no external crates unless already in the workspace). If a send would breach the cap, the request AWaits until the oldest timestamp exits the window (bounded wait — if wait exceeds a sane cap, e.g. 2x window, fail with a clear 'rate limited' error so clients don't hang forever).

- Client visibility: if there's a cheap way to surface 'paused Ns for provider quota' (existing status/event channel), do it; if it would require inventing new plumbing, SKIP it and note it in the report.
